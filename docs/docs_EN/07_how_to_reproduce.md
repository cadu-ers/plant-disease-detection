## Requirements

The project dependencies are listed in [`requirements.txt`](../../requirements.txt).
To install:

```bash
pip install -r requirements.txt
```

To download the dataset and prepare it in `data/` (at the repository root;
see [Manual execution](#manual-execution-script-by-script) about the
`PYTHONPATH`):

```bash
export PYTHONPATH=src            # in PowerShell: $env:PYTHONPATH = "src"
python -m dados.download_dataset
```

To also run the automated tests, install `requirements-dev.txt` (includes
`requirements.txt` and `pytest`):

```bash
pip install -r requirements-dev.txt
```

## Running by block (orchestrators)

The project has two blocks. The **Image Processing** block runs standalone;
the **Artificial Intelligence (AI)** block uses the outputs of the Image
Processing block, but the Image Processing block never depends on the AI
block.

```bash
python src/run_pi.py          # block 1: Image Processing
python src/run_ia.py          # block 2: AI (trains the CNN only if no model exists)
python src/run_all.py         # both blocks in sequence
```

Each orchestrator shows the list of steps at the start, runs each step in a
subprocess, skips steps whose outputs already exist ("[pulado] já existe",
i.e., "[skipped] already exists"), stops at the first step with an error
(showing the command to reproduce it) and ends with an
`etapa | status | tempo` (step | status | time) summary table.

| Script | Steps | Options |
|---|---|---|
| `run_pi.py` | download_dataset (only with an empty `data/`) → preprocessing → split_dataset → data_overview → segmentation_report → segmentation_report `--comparacao` → fft_analysis → histogram_analysis | `--force`: redoes everything (the download still only runs with an empty `data/`); `--so-figuras`: regenerates only data_overview, segmentation_report and fft_analysis (requires `data_processed/` and `data_split/`) |
| `run_ia.py` | train_model (only if `models/plant_disease_model.keras` does not exist; ~1h30 on CPU) → extract_features → hybrid_classifier → hybrid_classifier `--control-train-only` | `--treinar`: retrains the CNN; `--force`: redoes extraction and the hybrid classifier; `--sem-hibrido`: stops after the CNN |
| `run_all.py` | `run_pi.py` and then `run_ia.py` | `--force`: passed on to both |

`run_ia.py` first checks whether `data_processed/` and
`data_split/split_manifest.csv` exist; if they do not, it stops with the
message "Rode primeiro o bloco de Processamento de Imagens: python
src/run_pi.py" ("Run the Image Processing block first: python
src/run_pi.py").

The demos (`python src/demo_pi.py` and `python src/demo_ia.py`) remain
separate from the orchestrators.

## Image Processing demo (`demo_pi.py`)

Shows, on a single image, the whole Image Processing block: the segmentation
steps, the FFT and the HSV histograms with the actual ranges and thresholds
from `config.py`, plus the image's measurements compared with the class
median. It uses nothing from the AI block (it does not import `tensorflow`
and does not read `models/` or `features_cache/`, except for
`fft_features.csv` generated by `fft_analysis.py`).

```bash
python src/demo_pi.py                              # random image from the TEST set (manifest)
python src/demo_pi.py --classe Tomato_Early_blight # random test image from this class
python src/demo_pi.py caminho/da/imagem.jpg        # specific image
python src/demo_pi.py --seed 7                     # reproducible draw
python src/demo_pi.py --sem-janela                 # save only, do not open a window
```

Options can be combined (e.g., `--classe Tomato_Early_blight --seed 42
--sem-janela`); the only restriction is that an image path cannot be used
together with `--classe`. For a given image, the true class and the split
come from the manifest; if it is not in the manifest, the class comes from
the folder name (if it is a class in `data/`) or remains unknown.

The figure has 3 rows:

1. **Segmentation**: original, Gaussian blur, H channel, green mask, lesion
   mask, final mask (filled contour) and segmented leaf. The script checks
   that the final mask is identical to the one from `segment_image`.
2. **FFT**: prepared image (as in `fft_analysis.py`), log magnitude,
   low-pass (D0 = 15), high-pass and a panel with the measurements.
3. **Histograms (HSV space of the smoothed image)**: H channel of the whole
   image and of the leaf only, with the green hue range, the lesion hue
   range and the H 25–35 range, which belongs to both; S and V channels of
   the leaf and the background, with the minimum S and V thresholds of the
   lesion mask.

Measurements (in the terminal and in the figure panel): fraction of the
image covered by the leaf, lesion proportion on the leaf, % of leaf pixels
in the green and lesion ranges, and high/low frequency energy ratio (cutoff
at 0.25 of Nyquist). The leaf fraction, the lesion proportion and the
high/low ratio are shown alongside the median of the true class, computed
from `reports/pi/segmentacao/qualidade_segmentacao.csv` and
`features_cache/fft_features.csv`; if either of them does not exist, only
the image's value is shown.

Outputs in `rotina_demo/pi/`: `resultado_<timestamp>.png` (figure),
`resultado_<timestamp>.json` (path, true class, split and measurements) and
`ultima.json` (copy of the latest result, used by `demo_ia --ultima-pi`).

## AI demo (`demo_ia.py`)

Shows, on a single image, the AI block using the output of the Image
Processing block: the leaf is segmented with `segment_image`, classified by
the CNN (top 3) and by the hybrid SVM (CNN embedding + classical features),
and the two predictions are compared with the true class.

```bash
python src/demo_ia.py                              # random image from the TEST set (manifest)
python src/demo_ia.py --classe Tomato_Early_blight # random test image from this class
python src/demo_ia.py caminho/da/imagem.jpg        # specific image
python src/demo_ia.py --ultima-pi                  # same image as the last demo_pi run
python src/demo_ia.py --seed 7                     # reproducible draw
python src/demo_ia.py --sem-janela                 # save only, do not open a window
python src/demo_ia.py --verbose                    # show TensorFlow logs
```

Options can be combined (e.g., `--classe Tomato_Early_blight --seed 42
--sem-janela`); only one of image path, `--classe` and `--ultima-pi` can be
used at a time. `--ultima-pi` reads `rotina_demo/pi/ultima.json` (if it
does not exist: "rode antes python src/demo_pi.py", i.e., "run python
src/demo_pi.py first"), which makes it possible to show, in sequence and on
the same leaf, the Image Processing block and the AI block:

```bash
python src/demo_pi.py --classe Tomato_Early_blight --seed 42
python src/demo_ia.py --ultima-pi
```

Requirements: the CNN model (`models/plant_disease_model.keras` and
`models/class_names.json`; if missing, the message asks you to run
`python src/run_ia.py`). Without `models/svm_hybrid.joblib`, only the CNN
runs, with a warning.

How the predictions are made:

1. **CNN**: the input is the same as in training. The segmented image is
   encoded the way `preprocessing.py` writes it to `data_processed/`, then
   decoded and resized to 160x160 as in `extract_features.py`.
2. **Hybrid SVM**: the 147 classical features (`features.py`, as in
   `extract_features.py`) and the CNN embedding (output of
   `GlobalAveragePooling2D`, 1280 dimensions) form a row with the same
   columns in the same order as in training (`h_hist_00` ... `cnn_1279`);
   the script checks these columns against the ones stored in
   `svm_hybrid.joblib`.

Validation performed during development, on 26 test images (2 per class):
the CNN and SVM predictions were identical to those obtained from
`features_cache/` in 26/26 (maximum difference of 2.7e-6 in the softmax,
8.7e-6 in the embedding and 1.4e-14 in the classical features).

Outputs in `rotina_demo/ia/`: `resultado_<timestamp>.png` (original,
segmented leaf, CNN top 3 and a panel with the true class, predictions,
whether they agree and whether each one is correct) and
`resultado_<timestamp>.txt` (the same data).

## Manual execution, script by script

The scripts at the root of `src/` (`run_*.py` and `demo_*.py`) run directly
with `python src/<script>.py`. Those in subfolders (`dados/`,
`processamento_imagens/`, `ia/`) use absolute imports from `src/` (e.g.,
`from common.config import ...`) and run as modules, with `python -m`, from
the repository root and with `src/` on the `PYTHONPATH`. Just set the
`PYTHONPATH` once per terminal:

| System | Command |
|---|---|
| Linux / macOS (bash) | `export PYTHONPATH=src` |
| Windows (PowerShell) | `$env:PYTHONPATH = "src"` |

The orchestrators (`run_pi.py`, `run_ia.py`, `run_all.py`) already do this
on their own for the steps they run.

```bash
pip install -r requirements.txt
export PYTHONPATH=src            # in PowerShell: $env:PYTHONPATH = "src"
python -m dados.download_dataset
python -m processamento_imagens.preprocessing
python -m dados.split_dataset
python -m ia.cnn.train_model
python -m ia.hibrido.extract_features
python -m ia.hibrido.hybrid_classifier
python src/demo_pi.py
python src/demo_ia.py
```

Image processing material (figures for the presentation; they use the split
manifest. Only the SVM comparison in `fft_analysis.py` uses
`features_cache/handcrafted.csv`, from the AI block, and it is skipped if
the file does not exist):

```bash
python -m dados.data_overview
python -m processamento_imagens.segmentation_report
python -m processamento_imagens.fft_analysis
```

For a quick test of the hybrid classifier (few images and a reduced grid):
`python -m ia.hibrido.extract_features --limit 5` followed by
`python -m ia.hibrido.hybrid_classifier --quick`.

The Image Processing block also includes the old vs. new mask comparison
and the P1 histogram:

```bash
python -m processamento_imagens.segmentation_report --comparacao
python -m processamento_imagens.p1.histogram_analysis
```

Expert system (independent of the pipeline above; details in the
[Expert system](06_expert_system.md) section) and tests:

```bash
export PYTHONPATH=src            # in PowerShell: $env:PYTHONPATH = "src"
python -m ia.expert_system.diagnose src/ia/expert_system/exemplos/late_blight_tomate.json
python -m ia.expert_system.diagnose src/ia/expert_system/exemplos/late_blight_tomate.json --sem-cnn
python -m ia.expert_system.diagnose src/ia/expert_system/exemplos/ambiguo_early_target.json --interativo
python -m pytest -q
```

## Docker

With Docker Desktop and Docker Compose installed, build the image:

```bash
docker compose build
```

Run each pipeline step in a container. The generated files stay in the
workspace, since the project is mounted at `/app`:

```bash
docker compose run --rm -e PYTHONPATH=src app python -m dados.download_dataset
docker compose run --rm -e PYTHONPATH=src app python -m processamento_imagens.preprocessing
docker compose run --rm -e PYTHONPATH=src app python -m dados.split_dataset
docker compose run --rm -e PYTHONPATH=src app python -m ia.cnn.train_model
docker compose run --rm -e PYTHONPATH=src app python -m ia.hibrido.extract_features
docker compose run --rm -e PYTHONPATH=src app python -m ia.hibrido.hybrid_classifier
docker compose run --rm app python src/demo_pi.py --sem-janela
docker compose run --rm app python src/demo_ia.py --sem-janela
```

`-e PYTHONPATH=src` puts `src/` on the `PYTHONPATH` for the subfolder
scripts, as in manual execution. There is no display inside the container:
the demos (`demo_pi.py` and `demo_ia.py`) need `--sem-janela`. The figures
are saved to `rotina_demo/pi/` and `rotina_demo/ia/` in the workspace.

The orchestrators also work in the container:

```bash
docker compose run --rm app python src/run_pi.py
docker compose run --rm app python src/run_ia.py
```

The `Dockerfile` installs only `requirements.txt` (without `pytest`).

## Repository structure

```
.
├── data/                  # put the dataset in this folder!
├── docs/                  # technical documentation (this file and the others)
│   └── historico/         # full README prior to the reorganization (for the record)
├── features_cache/        # classical features, CNN embeddings and FFT descriptors (not versioned)
├── models/
│   ├── plant_disease_model.keras  # current model (generated by train_model.py, not versioned)
│   ├── class_names.json    # class order used in training
│   └── svm_hybrid.joblib   # best hybrid classifier pipeline (generated by hybrid_classifier.py)
├── reports/
│   ├── pi/                 # block 1: Image Processing (index in pi/LEIAME.md)
│   │   ├── dados/          # examples per class, dataset summary and split_summary.csv
│   │   ├── segmentacao/    # steps, old vs. new comparison and objective verification of the segmentation
│   │   │   └── estudo_limiares/  # comparisons with other S/V thresholds for the lesion mask
│   │   ├── fft/            # frequency domain analysis (fft_analysis.py)
│   │   └── p1_histograma/  # histogram before/after normalization (P1 material)
│   └── ia/                 # block 2: Artificial Intelligence (index in ia/LEIAME.md)
│       ├── cnn/            # train_model.py outputs (report, confusion matrix, metrics, history)
│       ├── hibrido/        # hybrid_classifier.py outputs (metrics, comparison, McNemar, control)
│       └── historico/      # old runs: baseline_v1/ and cnn_run1/, each with a README
├── src/
│   │   # Orchestration and demo (run with python src/<script>.py)
│   ├── run_pi.py           # block 1: Image Processing, step by step
│   ├── run_ia.py           # block 2: Artificial Intelligence (uses block 1 outputs)
│   ├── run_all.py          # runs run_pi.py and then run_ia.py
│   ├── demo_pi.py          # Image Processing demo (segmentation, FFT, HSV histograms)
│   ├── demo_ia.py          # AI demo (CNN top 3 + hybrid SVM on a single image)
│   │   # Subfolders (run with python -m, with src/ on the PYTHONPATH)
│   ├── common/             # common
│   │   ├── config.py           # shared constants (paths, sizes, seed, HSV thresholds)
│   │   ├── utils.py            # helper functions (list classes/images, draw an image, confusion matrix)
│   │   └── orchestration.py    # functions shared by the orchestrators (subprocess, plan, summary)
│   ├── dados/              # block 1: data
│   │   ├── download_dataset.py # downloads PlantVillage and copies the tomato/potato classes to data/
│   │   ├── split_dataset.py    # stratified training/val/test split (70/15/15) -> data_split/ + manifest
│   │   └── data_overview.py    # examples per class and resolution/format summary (reports/pi/dados/)
│   ├── processamento_imagens/  # block 1: Image Processing
│   │   ├── preprocessing.py    # image processing pipeline (segmentation -> data_processed/)
│   │   ├── segmentation_report.py # steps, objective verification and old vs. new comparison (reports/pi/segmentacao/)
│   │   ├── fft_analysis.py     # FFT: spectra, magnitude vs. phase, convolution theorem, descriptors
│   │   ├── features.py         # classical leaf features (color, lesion, GLCM, LBP) for the hybrid classifier
│   │   └── p1/
│   │       └── histogram_analysis.py  # histogram before/after normalization (P1 material, outside the pipeline)
│   ├── ia/                 # block 2: Artificial Intelligence
│   │   ├── cnn/
│   │   │   ├── model_utils.py      # model architecture used in training (augmentation + MobileNetV2 + head)
│   │   │   └── train_model.py      # CNN training
│   │   ├── hibrido/
│   │   │   ├── extract_features.py # extracts classical features + CNN embeddings -> features_cache/
│   │   │   └── hybrid_classifier.py  # SVMs (classical / CNN / hybrid) vs. CNN on the test set + McNemar + control
│   │   └── expert_system/      # expert system: knowledge base (YAML), inference engine and diagnose.py
│   └── tests/              # automated tests for the expert system (pytest)
├── requirements.txt        # dependencies to run the project
├── requirements-dev.txt    # requirements.txt + pytest
└── README.md
```
